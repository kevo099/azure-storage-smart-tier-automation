## Publisher finding and fix

The previous `scripts/publish-runbook.sh` uploaded with `az automation runbook replace-content --content @file`.
Azure CLI 2.90 and later drop the file's final newline during `@file` expansion, so the published runbook was one
byte short. Its fetch-back check read the content with `-o tsv`, which appends a newline, so the hashes matched and
the helper reported success. The runbook's behaviour is unaffected by the missing final newline, but the
provenance claim was false.

The publisher now uploads raw bytes and verifies both the draft and the published content from files written by
`az rest --output-file`, as in the Azure Backup automation repository. Run against the same Automation Account, it
reported the release SHA-256, and an independent raw fetch showed 51,360 bytes with SHA-256 `ba11f641…`.
